# Gnojo Roadmap

This roadmap reflects the state of the repository as of August 2026. Completed items describe working local-development features; planned items are not production commitments.

## Completed foundation

- [x] Flask application and service-oriented structure
- [x] Gnojo brand, navigation, responsive layout, and dark theme
- [x] Guided workflow runtime with history and resumable sessions
- [x] Device profiles and profile-aware recommendations
- [x] Universal search across workflows, articles, and commands
- [x] Workflow generation with Gemini and OpenAI fallback
- [x] Workflow editing, validation, simulation, export, versioning, and publication
- [x] Protected built-in workflows with editable copies
- [x] Knowledge drafting, validation, human review, and publication
- [x] Command library and command authoring
- [x] Cross-platform script library and script builder
- [x] Learning mode and workflow-linked knowledge
- [x] Feedback, history, coverage, and content-quality analytics
- [x] Automated accessibility and content-integrity coverage
- [x] Read-only Gnojo Curator audits with deterministic findings and review reports

## Current focus: trusted content library

- [ ] Review and improve every built-in workflow
- [ ] Expand Desktop Support, Networking, Windows, macOS, and Linux coverage
- [ ] Add authoritative sources to published articles
- [ ] Normalize titles, categories, platforms, difficulty, and estimated time
- [ ] Remove stale or unresolved cross-content references
- [ ] Expand reviewed commands and safe automation scripts
- [ ] Improve quality-dashboard actions and draft-reference reporting

## Repository and demonstration

- [ ] Add polished product screenshots and a short guided tour
- [ ] Add contribution and content-review guidance
- [ ] Add release notes and a public changelog
- [ ] Select a hosting platform and persistent-storage strategy
- [ ] Add production configuration and deployment checks
- [ ] Publish a read-only or safely sandboxed live demonstration
- [ ] Add the demonstration URL and status badge to the README

## Product hardening

- [ ] Add authentication and role-based author/reviewer permissions
- [ ] Replace or augment file storage with production-ready persistence
- [ ] Add CSRF protection, rate limits, audit logging, and security headers
- [ ] Add backup, restore, migration, and content-retention procedures
- [ ] Add browser-level end-to-end tests for critical authoring paths
- [ ] Add observability, structured logs, and deployment health checks

## Longer-term platform work

- [ ] Team collaboration and shared editorial queues
- [ ] Organization-level content libraries and policy controls
- [ ] Richer learning paths, labs, and assessments
- [ ] Additional operating systems, vendors, and infrastructure domains
- [ ] Content import with conflict resolution and provenance tracking
- [ ] Recommendation improvements based on reviewed outcome data

## Public release definition

A public release requires reviewed core content, secure production deployment, persistent data, documented operations, and a demonstration that cannot execute unsafe actions on visitor devices.
